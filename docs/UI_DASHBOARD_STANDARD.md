# Portal RYM · Dashboard Visual Standard

This document is the persistent visual baseline for dashboard work in Portal RYM.

## Direction
Dashboards should feel like a polished product, not a report or spreadsheet.

- Modern, vibrant and professional.
- Compact information density with strong hierarchy.
- Color has meaning and creates rhythm; avoid pale, washed-out surfaces.
- Important numbers should be readable at a glance.
- Cards should have personality, clear grouping and purposeful contrast.
- Use whitespace intentionally, but avoid oversized empty areas.
- Prefer visual explanations: sparklines, compact bars, badges and status cues.
- Charts must identify what is being shown. When space permits, show abbreviated day labels and amounts directly on/around bars.
- Secondary labels and monetary amounts must remain legible; do not reduce them to decorative micro-text.
- Operational priority order should be obvious without requiring interpretation.
- Keep sibling modules visually isolated; Panapass styles must not contaminate GPS, Revisados, Control Auto or Usuarios.

## Panapass reference
The approved Panapass Proposal 2 direction is the current benchmark:

1. Strong header with status/date/action.
2. Four colorful primary KPIs and compact secondary KPIs.
3. Attention, Payments and Context panels.
4. Galera comparison cards with distinctive colors, larger metrics and meaningful 7-day visualizations.
5. Galera charts should expose day + amount where space allows.
6. Prefer useful interactivity and progressive disclosure over dense mini-tables.

## Quality bar
Before calling a dashboard ready, verify:

- no overlapping text or numbers;
- no raw/loading skeleton flash;
- readable monetary values and secondary labels;
- charts have enough context to interpret quickly;
- desktop layout uses available space efficiently;
- responsive behavior remains usable;
- authenticated preview smoke passes;
- module CSS isolation passes.
